## 1. Problem - What problem are we solving?

Influsis connects creators and businesses for paid promotional work: businesses
post campaigns and gigs, creators discover and apply to them, deliver the work,
and get paid out through the app. It replaces ad-hoc influencer outreach
(DMs, spreadsheets, manual invoicing) with a single marketplace that handles
discovery, applications, delivery tracking, messaging, and payouts.

## 2. Users - Who is this for?

- **Creators** - individuals who produce content and want paid brand
  collaborations: browsing campaigns/gigs, applying, delivering work, messaging
  businesses, and withdrawing earnings (bank or bKash).
- **Businesses** - brands/companies that post campaigns and gigs, review
  creator applications, and manage active collaborations.

Both roles share the same app shell; screens and flows differ by role (see
`docs/screen/*`).

## 3. Features - What does the MVP need?

Already UI-complete against mock data (see Section 5 of `docs/PRD.md` and the
build plan for the full checklist):

- Onboarding, auth (sign-in/sign-up/OTP/forgot-password), and post-signup
  profile-verification wizard
- Home feed (campaigns, gigs, creators, businesses)
- Campaign and gig discovery, detail views, and creator applications
- Gig creation wizard (basics, pricing, preview)
- Order lifecycle (list, details, delivery submission, delivered confirmation)
- Creator and business profile pages
- Messaging (conversation list + chat)
- Notifications and search
- Balance, transactions, and withdrawal (bank transfer and mobile banking/bKash)
- Profile/account settings (edit profile, security, change password, privacy
  policy, help center)

Still needed before this is a real product rather than a UI shell: the
backend-integration roadmap (real API, real auth with route guarding,
replacing the fake user service and `data/*.ts` mocks with live data, app
identity cleanup) is being written manually in `build-plan.md`.

## 4. Data - What are we storing?

Modeled today as mock data + TypeScript types (`data/*.ts`, `types/*.ts`), to be
backed by a real API and database:

- Users (creators and businesses), with profile-verification fields (bio,
  categories, social media, languages, username, date of birth)
- Campaigns and gigs (business-authored listings)
- Applications (creator submissions to campaigns) and campaign invitations
- Orders (accepted work) and their delivery/status history
- Messages and conversations
- Notifications
- Balance, transactions, and withdrawal methods (bank accounts, bKash)

## 5. Tech - What stack are we using?

- **Framework**: Expo SDK 54, React Native 0.81.5, React 19.1, New Architecture
  enabled
- **Language**: TypeScript 5.9, strict mode
- **Routing**: Expo Router v6, file-based (`app/`), route files delegate to
  scene components (`scenes/`)
- **State**: Redux Toolkit + react-redux (`slices/`), `useAppSlice` convention
- **Local persistence**: AsyncStorage via a typed `useDataPersist` hook
- **Styling**: `StyleSheet.create`, per-screen style modules under `styles/`,
  design tokens from `theme/` (colors, fonts, spacing, radius, shadows)
- **Testing**: Jest + React Native Testing Library; every reusable component in
  `components/elements/` ships a co-located `*.test.tsx`
- **Build/deploy**: EAS Build (iOS/Android), EAS Update for OTA, EAS Hosting for
  web; GitHub Actions run format+lint+test on PRs/pushes
  (`.github/workflows/test.yml`) and publish an EAS preview channel
  (`.github/workflows/preview.yml`)

## 6. Monetize - How will this make money?

Commission on payouts: Influsis takes a percentage cut of the payments that
flow from businesses to creators through the app's balance/withdrawal system.

> TODO (confirm): exact commission rate, who it's deducted from (creator payout
> vs. business charge), and whether any subscription/listing-fee tier is added
> later are not yet decided.

## 7. UI/UX - How should this look and feel?

Documented in detail in `docs/design-system.md` and per-screen specs under
`docs/screen/*`; both already reflect the real Figma design (not the original
boilerplate look). Automatic light/dark theme support via `useColorScheme` and
a centralized color palette (`theme/colors.ts`). Follow those existing docs
before improvising new UI patterns.

## 8. Deployment - Where and how will this ship?

- **App type**: Expo-managed React Native app, multi-platform (iOS, Android,
  Web) from a single codebase
- **Build**: EAS Build for iOS/Android per `eas.json` profiles; `expo export`
  for web
- **Distribution**: EAS Update (OTA) for JS-only changes; EAS Hosting for web
  deploys
- **Environments**: dotenvx-managed env files (`.env.dev`, plus `.env.prod.example`)
  with typed access via `utils/config.ts`; secrets pushed to EAS via
  `npm run dev:secret:push`
- **CI**: GitHub Actions already run tests on PR/push
  (`.github/workflows/test.yml`); no automatic Verify-style GitHub check named
  yet (see `/ci`)
